# TXT 章节识别：从规则到模型的完整历程与经验

> 记录 weread 项目「txt 自动识别章节目录」这条线的全过程、关键决策、踩过的坑与可复用的经验。
> 配套的阶段性计划见 [chapter-detection-plan.md](./chapter-detection-plan.md)；这份文档偏「为什么这么做、学到了什么」。

## 1. 问题与初始判断

**问题**：用户导入任意格式的 txt，要自动切分章节、提取目录。txt 无固定格式。

**最初被提议的方案**：直接训一个小模型（mDeBERTa-v3-base）端到端识别。

**当时的判断（事后证明只对了一半）**：先别训模型，用「规则候选 + 全局验证」三层流水线，理由是章节标题表面模式极强（第 X 章、Chapter N），正则能覆盖 95%。训练有「数据死结」——自动标注只能来自自己的正则，模型只会学成正则的模仿者。

这个判断**在没有真实语料时是合理的，但被数据推翻了**（见第 3 节）。教训：架构直觉要尽早用真实数据验证，别在空气里论证覆盖率。

## 2. 三层规则流水线（P1，仍是基座）

`lib/chapter/` 落地了三层：

1. **候选生成** `patterns.ts` + `candidates.ts`：多语言模式库（第 X 章/Chapter N/一、/1./罗马数字/序章后记/【】），逐行匹配，行长过滤。
2. **全局验证** `validate.ts`：家族竞争打分、最长递增子序列剔除离群、最小间距过滤、覆盖度检查。**这层是精度的真正来源，且语言无关。**
3. **兜底**：无命中则整本一章。

关键设计：`detectChaptersDetailed` 输出置信度（high/medium/low/none），供后续决定是否上模型。

**这层的核心价值观后来变了**：一开始它是「主力」，后来变成「模型的高精度自动标注器 + 兜底」。

## 3. 真实语料撕碎了「95% 覆盖」的假设

拿到 `literature-books-master`（273 txt + 85 epub）后，在其上评估规则层：

- high 置信度只有 **147/273（54%）**，完全未识别 **96/273（35%）**——远低于计划里写的「~95%」。
- 失败归因（写了 `diagnose.ts` 定量）：52 本零候选（无任何已知标记）、22 本候选不足、10 本被 30% 前缀检查误杀（多卷本编号重启）。
- **金庸小说全军覆没**：回目是「一 青衫磊落险峰行」——中文数字 + 空格 + 语义标题，无「章」字。
- **《四世同堂》用裸数字 `01`/`02`**；《狼图腾》用「正文 1」。

**尝试补正则，一次改动的实测代价：修好 28 本、碰坏 13 本、23 本误报爆炸**（「世界营销绝招 800 例」被切成 522 章）。

> **经验 1（最重要）**：纯正则识别自由格式文本会「打地鼠」——每放宽一条规则接住新格式，就在别处放进一批假阳性。这不是靠努力能绕过的，是方法本身的上限。必须用真实语料量化，否则会一直自我欺骗。

## 4. 路线反转：epub 目录解开了「数据死结」

关键发现：**85 个 epub 自带结构化目录（toc.ncx），是独立于规则的 ground truth**。这直接解除了当初反对训练的核心理由——标签不再来自自己的正则，而来自 epub 的真实目录。

于是决策：**提前上模型，规则层冻结在高精度（P1 版本）当自动标注器 + 兜底**。

架构定位（始终没变）：

```
候选层：模型逐行「是否标题」分类   ← 学正则学不会的语义标题
   +   规则模式库（高精度冻结）     ← 引导标注 + 模型未加载时兜底
结构层：多卷拼接/目录页剔除/覆盖度   ← 永远是 validate.ts，模型不碰
```

> **经验 2**：模型替换的是**候选生成**，不是整条流水线。全局结构问题（编号跨卷拼接、目录页 vs 正文、覆盖度）是模型解决不了的，必须留给确定性代码。逐行分类器只回答「这一行像不像标题」。

## 5. 训练踩的坑（每一个都值得记住）

数据管线 `ml/data/build_dataset.py`：epub 正文按 spine 拍平成行，命中 toc.ncx 标题的行标正，其余标负。84/85 解析成功，7983 正样本。

### 坑 5.1：类别不平衡直接崩

首次冷烟训练 f1=0。正负比 1:29，模型学成「全判非标题」——96% 准确率但零召回。

**解法**：负样本降采样（`train.py --neg-ratio`，默认 1:5），**只对训练集做，验证集保持自然分布**（否则精度虚高）。平衡后冷烟 f1=0.37。

> **经验 3**：极端不平衡下，先看 f1/召回而非 loss（全判负也有低 loss）。降采样只动训练集，评估集必须保自然分布，否则指标骗自己。

### 坑 5.2：DeBERTa-v3 微调发散成「死模型」

完整训练（batch 32、3 轮）又 f1=0。诊断（加载模型手动预测）发现：**对任何输入输出几乎相同的 logits**——「第一章」和正文句概率都是 0.42。这是 DeBERTa-v3 微调著名的不稳定性。

**定位方法**：冷烟（batch 16）能学、完整（batch 32）不能——回到冷烟已证配置（batch 16/lr 2e-5/2 轮），只改数据量这一个变量。修复后 f1 正常。

> **经验 4**：模型「死掉」时，别猜，直接加载它对几个已知样本预测——常数输出 = 没学到 / 发散，区别于「偏向多数类」。调试超参时一次只改一个变量，回到已知能 work 的配置。DeBERTa-v3 对 batch/lr 敏感，发散优先降 lr、减小 batch。

### 坑 5.3：eval-limit 加速带来的指标虚高（自己骗自己）

为加速迭代，训练时只在验证子集（保留全部正样本 + 抽 5000 负样本）上评估，报出 precision 0.88 / f1 0.59。**但这是假的**——负样本池被缩小近 8 倍，假阳性少算，精度虚高。

在**完整验证集**上，v1 真实是 precision 0.45 / recall 0.44。

> **经验 5（血泪）**：任何为加速而对评估集做的采样都会污染指标本身。加速开关只能用于「训练中粗略监控趋势」，**最终结论必须在完整、自然分布的评估集上得出**。这个错误让我一度对外报了虚高的数字，后来必须纠正——诚实比好看重要。

### 坑 5.4：目录第一项 off-by-one

接入阅读页时发现点目录第一项会跳过开头。根因 `titleIdPage` 用 falsy 判断记录首页，首章页码是 0 被当成「未赋值」覆盖。改成与 `undefined` 比较。附了回归测试，并**验证过测试真能抓到 bug**（回退修复后测试失败）。

> **经验 6**：写回归测试后，回退修复确认它真的会失败——否则可能写了个永远通过的假测试。第一版测试因为序言太短没复现 bug，加长后才有效。

## 6. 召回瓶颈与格式特征（关键突破）

阈值扫描（`threshold_sweep.py`）显示：v1 光调阈值，召回从 0.44 只能到 0.6，且精度崩到 0.09。因为模型的漏判是**自信的漏判**（语义标题给近 0 概率），降阈值捞不回。

**根因不在数据量，在特征**：模型只看到「文本行 + 前后行文本」，看不到人判断标题的真正依据——**这行是否短、是否以句号结尾、在全书什么位置、前后行相对长度**。拍平文本时这些信号丢了。

**解法**：把格式特征离散成 token 拼进输入（不改模型结构，导出 ONNX 零障碍）：

```
第一章 风雪夜 → "L1 P0 Q0 NX1 PV0 [SEP] 上一行 [SEP] 第一章 风雪夜 [SEP] 下一行"
```

- L0-3 行长桶、P0/1 是否句末标点结尾、Q0-3 位置四分位、NX/PV 前后行是否明显更长。
- **单一来源** `ml/textfeat.py`，前端 `lib/nlp/features.ts` 逐字复刻，**34 个测试断言两侧输出逐字相等**（参照值从 Python 生成）。

效果（完整验证集诚实值）：**召回 0.44 → 0.90**，精度 0.45 → 0.24。

> **经验 7**：当模型「自信地漏判」某类样本，往往是缺特征而非缺数据。人判断该类样本靠什么线索，就把那些线索显式喂进去。
>
> **经验 8**：训练/推理特征必须逐字一致，否则线上崩。把特征逻辑收进单一来源，另一侧复刻，并用「参照值断言」测试锁死——这是最容易静默出错、又最该测的地方。

## 7. 「高召回低精度」是正确的档位

精度 0.24 看着差，但对「模型接结构层」的架构是**理想档位**：

- 模型负责**别漏**（召回 0.90）——漏了结构层补不回。
- 假阳性交给 `validate.ts` 结构层清（散乱假阳性不构成递增序列、不满足覆盖度）——低精度正是结构层**能**修的。

> **经验 9**：不要孤立地看单个模型指标。在「模型 + 后处理」系统里，该把召回和精度的职责分给不同层：模型冲召回，确定性后处理保精度。脱离系统评价 0.24 精度会得出错误结论。

## 8. 评估的严谨性（用户的关键提醒）

用户追问：验证集和训练集是否同源、会不会过拟合。核查后：

- **按书划分**（`split_by_book`），同一本书不跨训练/验证——防风格泄漏，0.90 是在没训练过的书上测的。
- **去重在划分前**，防同一 (text,label) 跨边界。
- **瑕疵（主动坦白）**：只有训练集 + 验证集，无独立测试集；`load_best_model_at_end` 按验证集选 epoch，指标轻微乐观。
- **更强兜底**：literature 目录的**中文 txt 从没进过训练**（只用了 epub + 英文 txt），是完全独立的第三方测试集（`test_independent.py`）。

> **经验 10**：按「样本的自然分组」（这里是书）划分，而非按行随机，否则泄漏。只有 train/dev 时要主动说明模型选择带来的乐观，并尽量补一个既不训练也不选择的独立测试集。诚实交代评估的局限，比报一个漂亮数字重要。

## 9. 工程/环境经验

- **Python 版本**：本机 python3=3.14 太新，torch 无 wheel。用 python3.11 建 venv（`ml/.venv`）。
- **Mac 训练**：MPS（Apple GPU）可训 mDeBERTa-base，约 1-2 步/秒；完整训练 1.5-3h。**别同时开多个训练进程**——会抢 MPS 互相死锁在 step 0（踩过，表现为「静默无输出后退出」，实为多进程竞争）。
- **等待策略**：长任务用后台 + 完成条件轮询（`until ! pgrep ...`），不要手动 sleep 拼接。
- **磁盘**：Trainer 每轮存 checkpoint（各 3GB），训练后清理只留最终模型。
- **模型体积**：mDeBERTa-v3-base int8 ONNX ≈ 322MB（全量 250k 词表，多语言）。

## 11. 待办 / 后续方向

- 独立测试集数字回填，若召回仍 ~0.85+ 则泛化成立。
- 导出 ONNX → 前端候选层接入（模型输出 union 到规则候选 → validate.ts）→ app 用金庸/四世同堂/英文书验证端到端。
- 产品决策：322MB 模型进 PWA 的下载成本；移动端词表裁剪版；懒加载策略。
- 进一步提召回：目录手动编辑 UI 收集用户修正（source: manual）作为增量标注 → 迭代。
- 精度若仍不够被结构层消化：可提高训练 neg-ratio、或阈值上调。
